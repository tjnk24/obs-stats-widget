# Правила работы в этом репозитории

OBS Custom Browser Dock: React 19, antd 6, Redux Toolkit, react-router 8, CSS-модули, webpack + swc.
Панель открывается с диска (`file:///.../build/index.html`), ходит в obs-websocket на `127.0.0.1` и, при проверке обновлений, в API GitHub за последним выпуском.

## Раскладка кода

- **Страница - папка в `src/pages/<Страница>/`**: `index.ts` отдаёт роуты из `routing.tsx` (массив `RouteObject`), разметка - в `containers/page`, свои компоненты страницы - в её `components/` и `containers/`.
- **Компонент или контейнер - по тому, откуда данные.** Компонент страницы (`components/`) - только разметка по пропсам, без стора, сервисов и экшенов: `BitrateGraph`, `CongestionProgress`, `StatList`, `LagValue`. Контейнер (`containers/`) берёт данные сам - селектором, своим хуком с селектором (`useOutputCardView`, `useItems`) или через сервис - и сам вызывает сервисы и экшены; пропсом получает только элемент списка, который знает родитель (`target` у `OutputCard`). Поэтому карточка, которая рендерится в `map`, но сама достаёт свою статистику из стора (`OutputCard`), - контейнер. `containers/page` - сама страница: она может только расставлять контейнеры (`Settings`) без своих данных. Общие для нескольких страниц лежат в `src/components` и стор трогать могут (`AppRoute` - статус соединения, `ErrorBoundary` - `reportService`): отдельной `src/containers` нет.
- **Роуты собирает `pages/Core/containers/page/appRoutes.tsx`.** Импорт из `__pages/*` разрешён только там и в `src/index.tsx`, общее для нескольких страниц выносится в `src/{components,utils,selectors,services,reducers}`.
- **Утилиты, хуки и константы живут там, где их используют.** Нужное только одной странице лежит в её `utils/`, `hooks/` или `consts.ts`: уровня страницы, если её используют несколько контейнеров страницы, уровня контейнера - если один. В `src/utils` и `src/utils/consts.ts` остаётся то, что нужно нескольким страницам или не страницам: сервису соединения (`StatsTracker`, `discoverTargets`, константы протокола и моста), стору, `index.tsx`. Утилиты сервиса в `src/services` не переносим.
- **Имена - человекочитаемые, везде**: переменные, параметры, счётчики циклов, константы, функции, в TS и в Lua. Никаких `i`, `n`, `d`, `x`, `K`, `H0`, `t1`, `ror`, `cb`, `el` - имя говорит, что лежит внутри (`wordIndex`, `candidate`, `divisor`, `roundConstants`, `rotateRight`). Даже если так названо в стандарте или алгоритме - даём смысловое имя. Поля чужих протоколов (`op`, `d` в obs-websocket) при деструктуризации переименовываем: `{op: opCode, d: data}`. Неиспользуемый параметр - `_` плюс имя (`_output`, `_index`).
- **Сначала прецедент, потом код.** Новый роут, селектор, слайс, сервис пишутся так же, как соседние.
- **Выносим только то, что повторяется.** Разовый текст - в разметке, а не в `consts.ts`; хелпер с одним вызовом - в месте вызова.
- **Общие типы и енумы - в `src/types/<область>/`, по одному на файл**, имя файла равно имени типа (`src/types/targets/StreamTargetDto.ts`), импорт через `__types/<область>/<Тип>`, внутри `src/types` - относительно (`./GpuStatsDto`, `../i18n/LanguageEnum`). Области совпадают с назначением кода: `obs/messages` (сообщения и коды obs-websocket), `obs/requests` (запросы и их результаты), `obs/responses` (ответы, `obs/responses/outputs` - про выходы), `bridge`, `targets`, `stats/views` (вид карточек) и `stats/tracking` (подсчёт), `connection`, `i18n`, `app` (настройки и их миграции, роутинг, предзагрузка), `mock`, `update` (выпуск и версия) и `update/compatibility` (проверка совместимости); тип, которому нет пары, лежит в корне `src/types`. Типы общих функций и классов (`src/utils`, `src/services`) в их файлах не объявляем. Типы одной страницы или контейнера - в их `types.ts`. Отсутствие значения - `Nullable<T>` из `infrastructure/common`, а не `?:` у обязательного пропа.
- **Вложенных типов нет**: у поля, параметра, дженерика или приведения не пишем тип-объект на месте (`outputs: {name: string}[]`, `Nullable<{time: number}>`, `findResultData<{outputs: ...}>`, `({context}: {context: string})`). Каждый такой объект - отдельный именованный тип в своём файле по общим правилам (`BridgeOutputDto`, `OutputBytesSampleDto`), а поле ссылается на него. Это касается и `typings/*.d.ts` (`WebpackProcessEnv`) и кода сборки (`webpack/types/`).
- **Больше 7 файлов одного вида в папке - раскладываем по подпапкам по смыслу** (типы, утилиты, компоненты, модули Lua, функции PowerShell): по области, как `src/types/obs/requests` или `utils/<назначение>/`, а не по алфавиту или виду файла. Подпапки - не глубже трёх уровней от исходной папки, в каждой - тоже не больше 7 файлов, иначе делим её дальше. Подпапка из одного файла не нужна: такой файл остаётся уровнем выше. Добавляя файл в папку, где уже 7, сначала раскладываем папку. Не считаются корень репозитория (конфиги инструментов должны лежать там) и служебные папки инструментов (`.husky/_`, `node_modules`, `build`, `release`).
- **Утилиты** - в `utils/`, одна экспортируемая функция на файл, имя файла равно имени функции. Утилита считает данные (`formatPercent`, `getBridgeScriptPath`, `drawGraph` рисует на canvas), а не возвращает JSX. Функция, которая возвращает разметку (`renderLabel`), - это не утилита: если её рендерит одно место, разметка пишется прямо там (подпись строки - в `items.map` у `StatList`); если она нужна в нескольких местах или держит хуки - это компонент.
- **Цепочку вычислений для разметки выносим в хук**: если компонент считает по данным из стора несколько зависящих друг от друга значений (статус, этап, проценты, ключи текстов), это хук `use<Что>View` в `hooks/` контейнера. Хук сам берёт нужное из стора, сам вызывает `Date.now()`, сам всё считает и возвращает объект `<Что>ViewDto` (тип в `types.ts` контейнера) только с тем, что нужно разметке; отдельной утилиты под ним не заводим. Компонент деструктурирует результат: `const {statusText, errorText, isUpdateShown} = useUpdateCardView();`. Примеры: `update-card/hooks/useUpdateCardView`, `output-card/hooks/useOutputCardView`, `main-layout/hooks/useHeaderStageView`. Тексты хук может переводить сам (`t` из `useTranslation`) и отдавать готовые строки; если среди результата есть JSX (строки `StatList` с `CongestionProgress`), файл хука - `.tsx`. Одна простая константа (`hasLine` в `BitrateGraph`) остаётся в компоненте. Такой хук тестируется без рендера: `vi.mock('react-redux', () => ({useSelector: vi.fn()}))`; если хук берёт один слайс - `vi.mocked(useSelector).mockReturnValue({...})`, если несколько - `mockImplementation((selector: (state: BaseStore) => unknown) => selector(state))` с поддельным состоянием из `tests/consts.ts` (`STATE` и варианты `{...STATE, update: {...STATE.update, request}}` прямо в тесте). Переводы - `vi.mock('react-i18next', () => ({useTranslation: () => ({t: (key: string) => key, i18n: {language: 'en'}})}))`, тогда тест сверяет ключи. Время - `vi.setSystemTime`, версия панели - `vi.stubEnv('APP_VERSION', ...)` в `beforeAll`, откат - `vi.useRealTimers` и `vi.unstubAllEnvs` в `afterAll`.
- **Внутренних хелперов в файле утилиты, класса или компонента не держим.** Каждая функция уровня модуля - в своём файле. Если хелперы нужны одной утилите или классу, они лежат с ней в одной папке: `utils/stats/StatsTracker/{StatsTracker.ts, createOutputState.ts, isStatusRequestOf.ts, index.ts}`, где `index.ts` реэкспортирует главную функцию, и импорт снаружи не меняется. Хелперы компонента - в его `utils/`.
- **Утилиты одного назначения - в общей папке** `utils/<назначение>/`: в `src/utils` это `requests` (батчи obs-websocket), `targets` (какие выходы и площадки), `stats` (подсчёт статистики), `auth` (хэш пароля), `bridge` (данные скрипта-моста), `mock` (симулятор OBS для моков), `settings` (версия и миграции настроек), `update` (версии, разбор выпуска GitHub, проверка совместимости). Внутри папки файлы импортируют друг друга относительно (`./`), снаружи - через `__utils/<папка>/<файл>`.
- **Поля класса разделяем пустой строкой**, как и методы: однострочные объявления подряд без отступа не пишем.
- **В папке компонента или контейнера - один `.tsx`.**
- **Порядок в начале компонента и хука**: селекторы redux (`useSelector`) -> стейты (`useState`) -> хуки (`Form.useForm`, `useTranslation`, `theme.useToken`, `useMatch`, свои хуки, `useRef`) -> объявления констант (производные данные, обработчики), затем эффекты и `return`. Группы разделены пустой строкой. Селекторы идут подряд, стейты тоже; а каждый хук и каждое объявление константы (и после раннего `return`, и внутри ветки `if`) отделены от соседних пустой строкой. `useTranslation` никогда не стоит первым, если есть селекторы или стейты.
- **Отдельный компонент или контейнер - только когда он оправдан**: используется в нескольких местах, рендерится в `map` и держит хуки, или несёт свою логику (эффекты, canvas, расчёт). Обёртка, которую рендерит одно место, - разметка в родителе: контейнер, который и есть всё содержимое страницы, сливается со страницей (`Login` - форма прямо в `containers/page`), обёртка над одним компонентом antd без своей логики (`Tag`, `Alert` с готовыми пропсами) пишется на месте.
- **Громоздкий контейнер с несколькими состояниями делим**: родитель только выбирает, что показать, и возвращает дочерний контейнер или короткий `Alert`, а каждое состояние со своей логикой - отдельный контейнер рядом.
- **Контейнер берёт данные сам, без проброса пропсами**: селектор, вычисление по нему и обработчик (вызов сервиса или экшена) пишутся внутри контейнера. Это так, даже если родитель уже выбрал те же данные или посчитал то же значение для своего решения. Утилита, нужная нескольким контейнерам страницы, лежит в `utils/` страницы. Пропсом приходит только то, что знает один родитель, - элемент списка в `map` (`target` у `OutputCard`). Если данные из стора могут быть `null`, а родитель показывает контейнер только когда они есть, контейнер всё равно берёт их сам, и его хук возвращает `null`, если данных нет.
- **Константы рядом с функциями не держим**: константа уровня модуля (`const RUNNING_STAGES = [...]`, шаблон `RegExp`, код ответа, путь) уходит в ближайший уже существующий `consts.ts` вверх по дереву: для всего в `src/utils/**` и для сервисов - общий `src/utils/consts.ts`, для `webpack/**` - `webpack/consts.ts`, для страницы - её `consts.ts`. Новый `consts.ts` в папке не заводим, если выше уже есть подходящий; свои `consts.ts` есть только у мест с большим набором собственных данных (`utils/mock/MockObsSimulator`, `scripts/*`, тестовые `tests/consts.ts`). Исключения - `initialState` слайса (остаётся рядом с `createSlice` в файле слайса), файлы, которые сами целиком данные без функций (словари `i18n/locales`, `routes.ts`, массивы роутов, `theme.ts`), и созданные объекты (экземпляры сервисов, `store`, `router`).
- **Тип объявляем только у констант-объектов и массивов объектов** (`DEFAULT_SETTINGS: SettingsDto`, `PLATFORM_RULES: PlatformRuleDto[]`, словари `Record<...>`), словари с одинаковыми ключами - енумами. Числа, строки, `RegExp` и массивы простых значений пишем без типа (`RECONNECT_INTERVAL_MS = 3000`), кроме случаев, когда вывод TypeScript не подходит: кортеж для antd (`PROGRESS_SIZE: [number, number]`), `string[]` из `Object.values` енума для сверки со строкой (`UPDATE_STAGES`), `Nullable<...>` с начальным `null`.
- **Деструктуризация до 4 полей - в одну строку, от 5 - столбиком**, по полю на строку: `const {latest, bridge, request} = useSelector(updateSelector);`, `const {Ok, Warn, Bad, Off} = HealthLevelEnum;`, `({titleKey, isAuthRequired, isLoginPage, children}: Props)`. Так и для пропсов компонента, и для енумов, и внутри функций. Eslint следит за этим сам (`object-curly-newline` для `ObjectPattern`: `minProperties: 5`, `consistent: false`), но поля столбиком при 5+ расставляем руками: `--fix` переносит только скобки.
- **Тернарник в одну строку - только короткий и одноуровневый**: простые ветки, вся строка заметно короче лимита (`type={isClosed ? 'error' : 'info'}`). Вложенный тернарник - всегда столбиком: условие, `? ветка` и `: ветка` на своих строках, вложенный - с ещё одним отступом (`strokeColor` в `CongestionProgress`, `value` в `OutputCard`). Длинный одноуровневый (сложные ветки - вызовы с аргументами, шаблонные строки) - тоже столбиком. Если строку удлиняет тернарник внутри атрибута JSX, вызова `t()` или шаблонной строки, он уходит в константу с понятным именем выше (`message`, `errorKey`, `memoryText`, `mainKbps`); если константу там не завести (аргумент в `case` у `switch`), аргументы вызова пишем столбиком.
- **Члены енума не пишем через точку раз за разом**: в начале файла (после импортов) енум деструктурируется - `const {Preparing, Downloading} = UpdateStageEnum;`, дальше ключи и значения короткие (`[Preparing]: ...`, `{value: En, ...}`, `stage === Done`). Правило для любого файла, где члены одного енума встречаются больше одного раза: словари в `consts.ts` (`ANTD_LOCALES`, `UPDATE_STAGE_TEXTS`, список языков), ресурсы i18n, компоненты, сервисы (`Checking`, `Failed` в `updateService`), утилиты (`getInstallBlocker`, `checkCompatibility`) и `case` в `switch` (`MockObsSimulator`). Единственное упоминание можно оставить через точку. Если короткое имя уже занято другим енумом в том же файле (`Identified` есть и в `ObsOpCodeEnum`, и в `ConnectionStatusEnum` в `obsConnectionService`), второй енум остаётся через точку.
- **Комментариев в коде нет совсем** - ни в TS, ни в SCSS, ни в Lua, ни в конфигах. Остаются только директивы инструментов (`/* eslint-disable ... */`, `/// <reference ... />`). Пустой `catch` без комментария - `catch { return; }`.

## Скрипт-мост (Lua)

- **`obs-script/streamoscope-bridge.lua` - загрузчик**, код моста - в `obs-script/streamoscope-bridge/main.lua`. OBS хранит путь к загрузчику в своих настройках, поэтому он не переезжает. Загрузчик читает `current-version.js` рядом с собой: если файл есть (установка), мост берётся из `versions/<версия>/`, если нет (ручная установка, папка проекта) - из той же папки. Он подменяет глобальную `script_path()` на эту папку, поэтому остальной код о версиях не знает, и добавляет в `package.loaders` поиск модулей через W-функции: штатный `require` открывает файлы в кодировке ANSI и не находит их, если в пути кириллица. Загрузчик - единственный файл моста, которому нельзя взять `consts.lua` и другие модули, поэтому константы и объявления FFI у него свои.
- **`streamoscope-bridge/main.lua` - только точка входа**: подключает модули и отвечает OBS (`script_description`, `script_load`, `script_unload`, события фронтенда). Логики в нём нет.
- **Автооткат ведёт загрузчик моста**: он единственный не меняется вместе с версией, а панель и код моста новой версии как раз и могут быть сломаны. Обновлятор перед переключением пишет `update-trial.txt` (`version`, `previous`, `panel`, `process`, `launches`). Панель через `HEALTH_REPORT_DELAY_MS` (1 с) после появления моста с обновлятором, если `ErrorBoundary` не поймал ошибку (`updateService.reportRenderError`) и это не dev-сервер, шлёт `healthy:X.Y.Z`; мост пишет `healthy-version.txt` и, если версия совпала с пробной, удаляет `update-trial.txt`. Загрузчик: мост новой версии упал при `require` - сразу откат и запуск прежней версии в той же сессии; упал в `script_load` - откат, новая версия заработает со следующего запуска. В первом запуске новой версии загрузчик ждёт `OBS_FRONTEND_EVENT_FINISHED_LOADING` и ещё `TRIAL_VERDICT_DELAY_SEC` (5 с, решение пользователя: с неработающей панелью OBS перезапускают сразу); если события нет - `TRIAL_VERDICT_FALLBACK_SEC` (30 с) с загрузки. Панель к этому времени не отчиталась и `panel=1` - откат прямо в этой сессии, и следующий запуск сразу откроет рабочую версию. Откат: атомарная замена `current-version.js`, запись `rolled-back-version.txt`, удаление пробного файла; если папки прежней версии нет, отката нет. Если медленная панель всё-таки отчиталась позже, мост возвращает её версию и стирает отметку об откате (`confirm_version`). `panel=1` только если прежняя версия когда-то отчиталась (`Write-UpdateTrial`): иначе молчание панели (выключен WebSocket, неверный пароль) ничего не доказывает, и пробный файл просто стирается. Запуски новой версии считаются поштучно на процесс OBS (`process`: смена коллекции сцен тоже перезагружает скрипт, а сессию, в которой версия скачана, отмечает обновлятор): если проба так и не дошла до решения за `TRIAL_MAX_LAUNCHES` (2) запуска (OBS падает или его сразу закрывают), на следующем запуске откат выполняется ещё до загрузки моста. Выпуск старше или равный откаченной `-Auto` не ставит (`rolledBack`), кнопка «Обновить» ставит, и удачная установка стирает отметку.
- **Описание в окне скриптов OBS** (`script_description`) - HTML: сверху иконка `streamoscope-bridge/icon.png` по пути из `script_path()` (`DESCRIPTION_ICON_HTML`), дальше текст на русском или английском по языку OBS.
- **Модули - в соседней папке `obs-script/streamoscope-bridge/`**, подключаются `require('streamoscope-bridge.<модуль>')` и находятся поиском из загрузчика. Префикс `streamoscope-bridge.` обязателен: загрузчик ищет только такие имена, а без него `require('json')` нашёл бы чужой файл.
- **Модули разложены по назначению**, как папки в `src`: `consts.lua` (константы и `BRIDGE_VERSION`) и `publisher.lua` (собирает данные и пишет их в параметр профиля) - в корне; `hardware/` - `gpu` (счётчики PDH), `gpu_names` (имена видеокарт через DXGI), `system_memory`; `outputs/` - `stream_outputs` (все выходы через FFI к libobs), `named_outputs` (запасной путь через `obslua`), `targets` (выбирает путь и обрезает адрес до схемы и хоста); `utils/` - `json` (кодировщик), `wide_string` (UTF-8 <-> UTF-16 для WinAPI), `environment` (переменные окружения), `text_file` (есть ли файл, чтение, запись и удаление), `process` (запуск процесса без окна); `update/` - `updater` (класс `Updater`: команды, фоновая проверка, отчёт панели о здоровье и статус обновления) и `release_links` (команда открыть страницу выпуска); в `utils/` ещё `profile_parameter` (`take`: прочитать параметр профиля и сразу стереть, общий для обеих команд). Подключение - полным путём: `require('streamoscope-bridge.hardware.gpu')`. `init.lua` OBS не находит (в `package.path` он добавляет только `/?.lua`), поэтому у модуля папки - обычное имя.
- **Источник с состоянием - класс, без состояния - модуль.** Класс (`Gpu`, `StreamOutputs`) - таблица с `Class.__index = Class`, конструктор `Class.new()` возвращает `setmetatable({...}, Class)`, открытые методы - `function Class:method()`, состояние - поля `self`. Приватные помощники класса - `local function helper(self, ...)` в его файле: так их действительно не видно снаружи, а методы с `_` - видно. Конструктор не падает, если источник недоступен (не Windows, нет DLL): объект создаётся, а `sample`/`read` возвращают `nil`. Экземпляры создаёт `script_load` (`open_sources`), закрывает `script_unload` и событие выключения скриптов (`close_sources`), в `publisher` они приходят параметром `sources`. Модуль без состояния - таблица функций (`targets.read`, `json.encode`), его `local`-функции и константы - тоже приватные. Имя файла - snake_case, переменная класса при подключении - PascalCase (`local Gpu = require(...)`), модуля - snake_case.
- **Константы - только в `consts.lua`** (корень `streamoscope-bridge/`, один на весь мост): числа WinAPI, шаблоны, пути счётчиков, GUID и прочие `local ИМЯ = ...` в модулях не держим, модуль обращается к ним как `consts.ИМЯ`. Если имя без контекста непонятно, у него префикс модуля (`JSON_ARRAY_METATABLE`, `TEXT_FILE_MAX_READ_BYTES`). Таблица модуля (`local gpu_names = {}`), класс и его `__index` - не константы.
- **`obslua` - через `local obs = obslua`** в каждом модуле, которому он нужен; глобальных переменных не заводим. Объявления FFI (`ffi.cdef`) - в модуле, который их использует, в `pcall`: повторное объявление типа - ошибка.
- **Пути и переменные окружения - только через W-функции Windows** (`environment.get`, `text_file`, `process.start_hidden`, строки через `wide_string`). `os.getenv`, `io.open` и `os.execute` работают в кодировке ANSI и ломаются на кириллице в имени пользователя, а `os.execute` ещё и мелькает окном консоли.
- **Обновление - канал команд через параметр профиля.** Панель пишет `[StreamoScope] UpdateCommand` (`SetProfileParameter`), мост на каждом тике читает его и сразу стирает (иначе после перезапуска OBS команда сработала бы снова). `install:X.Y.Z` запускает `updater/Update-Widget.ps1 -Version X.Y.Z` скрытым PowerShell с рабочей папкой `%TEMP%`, `auto:on` и `auto:off` мост записывает в `%LOCALAPPDATA%\streamoscope\auto-update.txt`, `healthy:X.Y.Z` - отчёт панели для автоотката; остальное просто стирается. Панель присылает `auto:*` при появлении моста с обновлятором и при смене свитча. Настройка лежит в файле, а не в параметре профиля, чтобы фоновая проверка не зависела от профиля и от панели. Сам мост запускает `Update-Widget.ps1 -Auto` через `AUTO_UPDATE_START_DELAY_SEC` (60 с) после загрузки и затем раз в `AUTO_UPDATE_INTERVAL_SEC` (сутки), если в файле не `off` (`Updater:handle_schedule`). В данных моста - блок `update`: `available` (есть ли обновлятор: `updater/Update-Widget.ps1` в папке версии и `minisign.exe` в `updater` папки установки, `UPDATE_SIGNATURE_TOOL_PATH`) `status` - содержимое `%LOCALAPPDATA%\streamoscope\update-status.json` строкой JSON, как есть (панель разбирает сама), и `rolledBackVersion`, если была откачена версия. При ручной установке и из папки проекта обновлятора нет (`available: false`). Второй параметр - `[StreamoScope] OpenUrlCommand` = адрес: встроенный Chromium OBS открывает ссылки из панели в своём окне, где не скачать файл, поэтому «Что нового» и «Скачать вручную» просят мост открыть адрес в браузере по умолчанию. Мост открывает только адреса, которые начинаются с `https://github.com/tjnk24/streamoscope/` или `http://127.0.0.1:` (тестовый выпуск), состоят из безопасных символов URL (без пробелов, кавычек и `<>`) и не длиннее 2048, - через `rundll32.exe url.dll,FileProtocolHandler <адрес>` из `%SystemRoot%\System32` (`process.start_hidden`, а не `ShellExecuteW`: таймеры скриптов идут не в главном потоке, где инициализирован COM). Остальное просто стирается. Команды мост читает своим таймером раз в `COMMAND_INTERVAL_MS` (250 мс), данные публикует раз в `PUBLISH_INTERVAL_MS` (3 с). `BRIDGE_VERSION` - 2 с появлением канала команд (открытие ссылок вошло в ту же версию), 3 - с переименованием раздела параметров `[ObsStatsDock]` в `[StreamoScope]` (выпуск 0.3.0), 4 - с загрузчиком, папками версий и фоновой проверкой.
- **JSON не склеиваем строками**: собираем обычную таблицу и отдаём `json.encode`. Пустой массив - `json.array({})`, иначе он станет `{}`; явный `null` - `json.null`, поле со значением `nil` просто не попадает в JSON.
- **Ошибка одного источника не роняет скрипт**: создание источников в `script_load` и каждое чтение в `publisher` - в `pcall`, без данных поле просто пропадает.
- **Имена - snake_case**, как в Lua принято, остальные правила имён и «никаких комментариев» - те же, что для TS.
- **Проверка без OBS**: LuaJIT из `lua51.dll` в папке установки OBS можно запустить через Python `ctypes` с заглушкой `obslua`; libobs вне OBS не вызываем (перечисление выходов подменяем заглушкой). В настоящем OBS - Инструменты → Скрипты → «Перезагрузить скрипты», затем «Скопировать диагностику» в панели.

## Настройка OBS установщиком (PowerShell)

- **`installer/configure-obs.ps1` - точка входа** для Inno Setup: параметры (`-Mode Install|Uninstall`, `-InstallDirectory`, `-ObsDirectory` для portable, `-ConfigDirectory`, `-DataDirectory`), подключение функций из `installer/ConfigureObs/` и код выхода `ConfigureObsResult` (`0` готово, `1` ошибка и откат, `2` OBS запущен, `3` OBS ещё не запускали, `4` незнакомый формат, ничего не тронуто, `10` готово, но настроек obs-websocket ещё нет). На экран скрипт ничего не пишет: подробности - в `%LOCALAPPDATA%\streamoscope\configure-obs.log`, резервные копии - в `backups\<время>` рядом (последние 5).
- **Функции разложены по папкам** `installer/ConfigureObs/`: `json/` (разбор с позициями и экранирование), `ini/`, `files/` (чтение и запись с проверкой, резервные копии и откат, журнал), `edits/` (правки настроек OBS), `paths/` (поиск OBS, portable, пути, запущен ли OBS); в корне - `Invoke-ConfigureObs`, `Get-ObsChanges` и `ConfigureObsResult`. Точка входа и тесты подключают их рекурсивно (`Get-ChildItem -Recurse`), установщик копирует с подпапками.
- **Одна функция - один файл** `Глагол-Существительное.ps1` (одобренные глаголы PowerShell), переменные - camelCase. Правка текста (`Add-BridgeScript`, `Add-BrowserDock`, `Set-IniValue`, `Enable-WebSocketServer`) - чистые функции «текст на входе - текст на выходе», файлы читает и пишет только `Get-ObsChanges` и `Save-ObsChanges`.
- **Файлы OBS не переписываем целиком.** PowerShell 5.1 при `ConvertFrom-Json`/`ConvertTo-Json` меняет числа, экранирование и вложенность. `Read-JsonValue` разбирает JSON с позициями, и правка вставляет или заменяет только нужный кусок (элемент `scripts-tool`, значение `server_enabled`); ini - только одна строка. Остальной файл остаётся байт в байт прежним, BOM и переводы строк сохраняются.
- **Порядок:** OBS закрыт (`Test-ObsRunning`) → пути (`Resolve-ObsPaths`: portable, `[Locations]`, `user.ini` или `global.ini` по правилам из `docs/obs-config.md`) → все правки считаются в памяти, ошибка разбора - выход без записи → резервные копии → запись через временный файл с проверкой и `File.Replace` → при любой ошибке все файлы восстанавливаются из копий → `install-manifest.json` в папке установки (что добавлено, для повторной установки и удаления). Повторная установка ничего не меняет; удаление убирает панель (по `uuid` или адресу) и мост из всех коллекций, сервер WebSocket не выключает. `user.ini` никогда не создаём, пароль obs-websocket не читаем и не пишем в журнал.
- **`PSModulePath` сбрасываем в начале точек входа** (`configure-obs.ps1`, `installer/tests/run-tests.ps1`) на пути Windows PowerShell: если `powershell.exe` запущен из PowerShell 7 (терминал, шаг GitHub Actions по умолчанию), он наследует модули седьмой версии и теряет команды вроде `Get-FileHash`.
- **Константы - в `consts.ps1` своей программы**: `installer/ConfigureObs/consts.ps1` и `installer/updater/UpdateWidget/consts.ps1` (`$script:Имя = ...`). Оба лежат рядом с функциями и подключаются тем же `Get-ChildItem *.ps1`, установщик копирует их вместе с функциями. В файлах функций `$script:`-констант нет; переменная состояния (`$script:ConfigureLogPath`) - не константа и остаётся у своей функции.
- **`$PSScriptRoot` не используем в значениях параметров по умолчанию**: при запуске через `-File` PowerShell 5.1 там его не заполняет. Папку скрипта берём в теле: `Split-Path -Parent $MyInvocation.MyCommand.Path`.
- **Внешние программы при `$ErrorActionPreference = 'Stop'`** не перенаправляем через `2>&1`: в PowerShell 5.1 их вывод в поток ошибок тогда становится исключением. Внутри функции, которая вызывает программу, ставим `$ErrorActionPreference = 'Continue'`, поток ошибок отбрасываем (`2>$null`), решение принимаем по `$LASTEXITCODE`.
- **Обновлятор - `installer/updater/Update-Widget.ps1`** с функциями в `installer/updater/UpdateWidget/` (`download/`, `versions/`, `rollback/`), входит в выпуск и лежит в `versions/<версия>/updater`, поэтому обновляется вместе с программой. `minisign.exe` - только в `{app}\updater`, его кладёт установщик: скачанные программы мы не запускаем (решение пользователя). Папку установки и `minisign.exe` скрипт находит от своего положения. Запускает его мост: `-Version X.Y.Z` (кнопка «Обновить») или `-Auto` (фоновая проверка), остальные параметры по умолчанию (адреса выпусков, публичный ключ строкой - тест сверяет его с `minisign.pub`, файл статуса `%LOCALAPPDATA%\streamoscope\update-status.json`). `-Auto` (`Invoke-AutoUpdate`) с пониженным приоритетом: не чаще раза в `AutoCheckMinIntervalHours` по метке `update-check.stamp` (неудачный запрос меткой не считается) берёт из API GitHub тег и дату последнего выпуска и решает (`Get-AutoUpdateAction`): не новее - `upToDate`, другая major-версия - `manualOnly`, не новее откаченной - `rolledBack`, выпуск моложе `AutoInstallDelayHours` (48 ч, чтобы успеть отозвать плохой) - `tooFresh`, иначе ставит. Порядок установки (`Invoke-UpdateWidget`): блокировка `update-status.json.lock` (второй запуск - `busy`) -> версия `X.Y.Z` и новее текущей из `current-version.js` (та же самая - сразу `done`, старше - `notNewer`) -> скачать и проверить подпись `compatibility.json`, сверить в нём версию и минимальную версию OBS с `obs64.exe` (`Get-ObsVersion` через `Find-ObsDirectory` из `ConfigureObs`) -> скачать `streamoscope-<версия>.zip` с процентами, проверить подпись -> распаковать в `versions/staging-<версия>`, проверить состав (`RequiredPackageFiles`) и версию внутри, переместить в `versions/<версия>` (`Expand-UpdatePackage`) -> записать `update-trial.txt` (`Write-UpdateTrial`) -> атомарно заменить `current-version.js` (`Set-CurrentVersion`, `File.Replace`): всё, что случилось раньше, текущую версию не трогает -> стереть `rolled-back-version.txt`, оставить три новые версии и версию для отката (`Remove-OldVersions`), обновить `DisplayVersion` в «Приложениях» -> `done`. Статус - JSON `{version, stage, percent, error, updated}`, этапы `preparing`, `downloading`, `verifying`, `installing`, `done`, `failed`; коды ошибок `invalidVersion`, `notNewer`, `network`, `signature`, `incompatible`, `install`, `unexpected`. Временные файлы - `%TEMP%\streamoscope-update-<версия>`, удаляются всегда. Тесты (`Update-Widget.Tests.ps1`) - на поддельном выпуске в `TestDrive` по `file:///` с временными ключами, версия OBS и запись в реестр подменяются `Mock`; `npm run test:installer` сначала достаёт `minisign.exe` (`scripts/buildInstaller/fetchMinisign.ts`).
- **Файлы `.ps1` - только ASCII**: PowerShell 5.1 читает файл без BOM в кодировке ANSI, и кириллица в нём ломается. Тексты для пользователя показывает установщик, а не скрипт.
- **Тесты - Pester 5+, `npm run test:installer`** (`installer/tests/run-tests.ps1`): `ConfigureObs.Tests.ps1` - чистые функции правки текста, `Invoke-ConfigureObs.Tests.ps1` - установка, повторная установка и удаление на образцах `installer/tests/fixtures/obs-28`, `obs-30`, `obs-33` (копируются в `TestDrive`, `__ROOT__` в `[Locations]` подменяется на путь копии), плюс запущенный OBS, отсутствие настроек, битая коллекция, сбой записи с откатом, portable и кириллица в путях. `Test-ObsRunning` в тестах подменяется через `Mock`. Образцы - выдуманные данные с настоящей структурой, личных путей и паролей в них нет; `.gitattributes` держит их байты как есть (`-text`). Новый случай в формате OBS - сначала образец и тест, потом правка скрипта. Только синтаксис, который есть и в Pester 5, и в 6: в GitHub Actions на Windows стоит пятый.
- **Как устроены настройки OBS** - `docs/obs-config.md`; при новом знании о формате дополняем его.

## Установщик (Inno Setup)

- **Иконка - `installer/images/`**: `streamoscope.ico` (иконка `setup.exe`, деинсталлятора и записи в «Приложениях» - файл копируется в `{app}`), картинки мастера `wizard-<ширина>.png` (страница завершения) и `wizard-small-<размер>.png` (угол остальных страниц) в трёх масштабах 100/150/200 %. Та же иконка - `docs/images/streamoscope-icon-512.png` (README, вместо баннера; из неё же нарезаны остальные размеры) `obs-script/streamoscope-bridge/icon.png` (описание моста в окне скриптов OBS) и `src/images/streamoscope-icon.png` 64 px (фавикон - опция `favicon` у `HtmlWebpackPlugin`; в шапке панели иконки нет - решение пользователя). Новая иконка - пересобрать все эти файлы из одного исходника.
- **`installer/streamoscope.iss`, сборка - `npm run package:installer`**: `package:release`, затем `scripts/buildInstaller` находит `ISCC.exe` (Inno Setup 6: `ISCC_PATH`, `%LOCALAPPDATA%\Programs`, `Program Files`) и передаёт `/DAppVersion`, `/DPackageDir` (папка выпуска) и `/DOutputDir`. Результат - `release/streamoscope-setup-<версия>.exe`.
- **Без прав администратора** (`PrivilegesRequired=lowest`): ставится в `%LOCALAPPDATA%\Programs\streamoscope` без выбора папки, запись «StreamoScope» в «Приложениях» с деинсталлятором - в HKCU. `AppId` не меняем никогда: по нему новая версия ставится поверх старой (единственная смена была при переименовании в 0.3.0).
- **Раскладка установки**: `dock/index.html` - загрузчик из `installer/loader/index.html`, подставляет `current-version.js` и переходит на `../versions/<версия>/dock/index.html` с сохранением `#`; `streamoscope-bridge.lua` - загрузчик моста; `current-version.js` (`window.STREAMOSCOPE_VERSION = 'X.Y.Z';`, его читают оба загрузчика, установщик пишет его в `WriteCurrentVersion`); `versions/<версия>/` - содержимое папки выпуска; `updater/` - `minisign.exe` с лицензией; `update-trial.txt`, `healthy-version.txt` и `rolled-back-version.txt` - файлы автоотката; `ConfigureObs/` и `configure-obs.ps1`. `[InstallDelete]` удаляет старые файлы, все версии, `update-status.json` (иначе карточка показала бы статус версии, которой больше нет) и `update-check.stamp`: запуск установщика - чистая установка; `[UninstallDelete]` - `versions`, `current-version.js` и файлы автоотката, потому что их Inno не ставил. Адреса `dock/index.html` и `streamoscope-bridge.lua` записаны в настройках OBS и не меняются. Ctrl+R в доке перезагружает текущую версию из её папки, а новая откроется при следующем запуске OBS: так панель и мост всегда переключаются вместе. Сохранённые настройки не теряются: у всех страниц `file://` в Chromium одно хранилище.
- **OBS настраивает `configure-obs.ps1`**, установщик только запускает его скрыто (`Exec` 64-битного `powershell.exe`, `SW_HIDE`) и переводит код выхода в текст: `2` - окно «закройте OBS и повторите попытку» по кругу, отмена - установка без настройки; `3`, `4`, `1` и `10` - пояснение на последней странице, там же всегда - где искать панель и пароль WebSocket. Удаление (`InitializeUninstall`) запускает `-Mode Uninstall` до удаления файлов; если OBS открыт и пользователь не закрыл его - вопрос «удалить только файлы?», «нет» отменяет удаление.
- **Тексты - `[CustomMessages]` на английском, русском, испанском, немецком и бразильском португальском** (языки самого Inno: `en`, `ru`, `es`, `de`, `ptbr`), новая строка - во все сразу. Названия меню OBS - дословно из его файлов перевода, как в разделе `obs` словарей панели (в немецком OBS «Docks» не переведено). Названий кнопок Windows («Повторить», «Отмена») в текстах нет: их подписывает Windows на своём языке. Файл `.iss` - UTF-8 с BOM, сообщения - через `SuppressibleMsgBox`, чтобы тихая установка (`/VERYSILENT /SUPPRESSMSGBOXES`) не зависала.
- **Живую установку запускает пользователь из Проводника, а не Claude.** Claude Desktop - пакет MSIX, и процессы, которые он запускает, работают в его контейнере: записи в HKCU и новые папки в `%AppData%`/`%LocalAppData%` уходят в личный реестр и `LocalCache` пакета (`%LOCALAPPDATA%\Packages\Claude_*`). Установщик, запущенный так, не появится в «Программах и компонентах», а его журнал и копии окажутся в `LocalCache`; изменения уже существующих файлов (настройки OBS, `%LOCALAPPDATA%\Programs`) при этом настоящие. Такую установку удаляют её же деинсталлятором из той же среды. Тихие проверки на копии настроек из Claude это не портит.
- **`minisign.exe` для обновлятора** скачивает `scripts/buildInstaller/ensureMinisign.ts`: официальный архив minisign по точной версии и SHA-256 из `scripts/buildInstaller/consts.ts`, распаковка встроенным `%SystemRoot%\System32\tar.exe` (GNU tar из Git zip не распаковывает), кэш - `node_modules/.cache/minisign/<версия>`. В репозитории бинарника нет. Установщик кладёт его в `{app}\updater` вместе с лицензией `installer/third-party/minisign-LICENSE.txt` (ISC). Меняем версию minisign - меняем версию и хэш в `consts.ts`.
- **Проверка обновления целиком - тестовой сборкой.** Переменные `TEST_UPDATE_SERVER` (`http://127.0.0.1:3063`) и `TEST_UPDATE_PUBLIC_KEY` при `npm run package:installer`: webpack подставляет `process.env.TEST_UPDATE_SERVER`, и панель берёт последний выпуск с `<сервер>/latest` (`LATEST_RELEASE_URL`), а `scripts/buildInstaller/stageTestUpdater` заменяет в `updater/Update-Widget.ps1` папки выпуска значения по умолчанию `ReleaseBaseUrl`, `LatestReleaseUrl` и `PublicKey`. Без переменных сборка обычная; подмены «на лету» в обновлятор не встраиваем, чтобы настоящую установку нельзя было перенаправить. Поддельный выпуск раздаёт `npm run serve:test-release -- <папка>` (`scripts/serveTestRelease`): `/latest` в формате GitHub API со строкой совместимости и старой датой публикации (иначе фоновая проверка ждала бы 48 ч) и файлы по `/download/v<версия>/...`, CORS открыт для страницы `file://`; `--broken-signature` отдаёт чужую подпись архива. В папку кладём подписанные `streamoscope-<версия>.zip` (верхний уровень архива - папка `streamoscope-<версия>`) и `compatibility.json`. Тестовый ключ (`minisign -G -W`) и более новую версию (копия проекта с поднятой `version` и ссылкой на `node_modules`) держим в черновой папке: `package:release` в начале удаляет всю `release/`. После проверки ставим обычную сборку. Обновлятор можно прогнать и без OBS на черновой раскладке установки с подменённым `LOCALAPPDATA`; настоящую установку это не трогает, кроме `DisplayVersion` в реестре: в копии `consts.ps1` подменяем `UninstallRegistryKey`.
- **Если на машине уже есть установка, тихий установщик ставит в её папку и игнорирует `/DIR`** (Inno берёт прежнюю папку по `AppId`). Проверки в черновой папке с подменённым `APPDATA` делаем только когда настоящей установки нет; иначе они обновят её файлы (настройки OBS при этом не тронуты: скрипт смотрит в черновой `APPDATA`).
- **Проверка без вашего OBS**: тихая установка в черновую папку (`/DIR=`) с подменёнными `APPDATA` и `LOCALAPPDATA` на копию настроек OBS, где пути `[Locations]` в `global.ini` переписаны на копию; до и после сверяются хэши настоящих файлов OBS.

## Локализация

- **Тексты интерфейса - только через i18next**, ни одной строки для пользователя в разметке, константах, утилитах и сервисе. В компоненте - `const {t} = useTranslation()` из `react-i18next`; вне React (утилиты, сервис, валидаторы) - `import {t} from 'i18next'`, числа - `i18n.language` из `i18next`. В константах храним ключ (`textKey: ParseKeys`), а не текст: константа вычисляется один раз при загрузке и не сменила бы язык.
- **Словари - `src/i18n/locales/`**, по одному файлу на язык. Эталон - `en.ts`, его тип `TranslationDto`; остальные объявлены как `TranslationDto`, поэтому пропущенный или лишний ключ - ошибка компиляции. Ключи для `t()` типизирует `typings/i18next.d.ts`. Подстановки - `{{name}}`. Новая строка добавляется во все словари сразу.
- **Названия меню и окон OBS - раздел `obs` словаря**, дословно как в OBS на этом языке: из `data/obs-studio/locale/*.ini` самого OBS, `core/obs-websocket/data/locale/*.ini` и `core/frontend-tools/data/locale/*.ini` в папке установки, без `&` горячих клавиш. Если у OBS перевода нет, он показывает английское название - берём его же. Подсказки ссылаются на них вложенным ключом i18next (`'$t(obs.tools) → $t(obs.webSocketSettings) → $t(obs.serverPort)'`), а не повторяют текст.
- **Языки** - `LanguageEnum`: английский (по умолчанию и запасной), русский, испанский, немецкий, бразильский португальский и «Жабий» (`ru-x-frog`). Пока язык не выбран вручную (`settings.language` - `null`), берётся язык OBS из `navigator.language` (`languageService.resolveLanguage`), а если его нет среди наших - английский; отдельного пункта «Как в OBS» в списке нет, там сразу стоит текущий язык. «Жабий» - только поправки к русскому (`DeepPartial<TranslationDto>`): чего в нём нет, i18next берёт из `ru`; настройки и поле порта в нём не задаются и остаются обычным русским.
- **Язык выбирается в настройках** - выпадающий список в карточке «Отображение», язык меняется сразу при выборе: значение лежит в `settings.language`, а сохраняет его и вызывает `i18n.changeLanguage` `languageService.setLanguage` - компонент только передаёт выбор. antd получает свою локаль в `CorePage` (`ANTD_LOCALES`).
- **`strictNullChecks` включён** - без него типы i18next превращают ключи в `never`.

## Данные и роутинг

- **Состояние - в Redux Toolkit.** Общие слайсы в `src/reducers`: `connection` (статус соединения, версия OBS, текущая коллекция сцен), `stats` (найденные выходы и данные карточек), `update` (последний выпуск, состояние проверки, обновлятор и статус от моста, запрос установки `request` с версией и временем), `@localStorage/settings` (сохраняется в localStorage мидлварой из `store.ts`).
- **Экшены без алиасов.** Общие слайсы - `commonActions` из `__actions` (`src/actions.ts`), импортируются под этим именем: `import {commonActions} from '__actions'`. У страницы со своими слайсами - `actions` в её `actions.ts`: `import {actions} from '../../actions'`. `bound as actions` и подобные переименования при импорте не пишем. Несвязанные с dispatch генераторы экшенов - `actionCreators` в `src/reducers/index.ts`.
- **Формат настроек - с версией и миграциями.** В сохранённых настройках есть номер `settingsVersion`; настройки без номера считаются версией 1. При загрузке `storageService` прогоняет их по цепочке функций перехода N -> N+1 до текущей версии и сохраняет. Поменял формат настроек (переименовал поле, поменял тип или смысл, разделил одно поле на несколько) - подними версию и допиши функцию перехода, которая переносит выбор пользователя, и тест на неё. Новое поле со значением по умолчанию миграции не требует. Функции перехода не удаляем никогда: кто-то обновится прямо с той версии. Настройки, которые не разбираются или пришли из более новой версии, откладываем и берём значения по умолчанию.
- **Селекторы плоские**, производные данные - в теле компонента. `createSelector` не используем.
- **У каждого слайса - селектор слайса** `connectionSelector`, `statsSelector`, `settingsSelector`, `updateSelector` (`state => state.<слайс>`), поля из него берём деструктуризацией. Один селектор в другой не вкладываем (ни `createSelector`, ни `state => updateSelector(state).latest`): слайсы всегда есть и типизированы, отсутствие значения уже `null` в `initialState`, а селекторы только достают поля и ничего нового не собирают, так что запоминать нечего.
- **В компоненте несколько полей одного слайса - одним селектором слайса**: `const {latest, bridge, request} = useSelector(updateSelector);`, а не по селектору на поле. Immer отдаёт новый объект слайса только при изменении, поэтому лишняя перерисовка бывает лишь от полей, которые компонент не берёт; для небольших `update` и `settings` и для компонентов, которые и так зависят от частых полей `stats` (`useItems` берёт `view` и `hardware`), это неважно. Точечный селектор поля (`connectionStatusSelector`, `statsTargetsSelector`, `statsViewSelector`, `settingsPortSelector`) заводим, только когда компоненту из слайса нужно одно поле: так он не перерисовывается от остальных. Селектор, который собирает новый объект (`state => ({a: state.x.a})`), не пишем: он перерисовывает компонент на каждое изменение стора.
- **Сервисы читают стор через селектор слайса**: `const {latest, bridge} = updateSelector(getStore());`, `settingsSelector(state).isMockEnabled`. Перерисовки сервиса не касаются, поэтому точечные селекторы ради него не заводим; точечный селектор, который больше никто не использует, удаляем (knip его покажет).
- **Хранилище - `services/storageService.ts`**: пароль (`loadPassword`, `savePassword`) и настройки (`loadSettings`, `saveSettings`). Ключи и безопасное чтение и запись (`private getItem`, `setItem`, `removeItem` ловят исключения `localStorage`) спрятаны внутри; напрямую к `localStorage` больше никто не обращается.
- **Соединение с obs-websocket - `services/obsConnectionService.ts`**, вне React: переход между страницами не рвёт связь и не сбрасывает графики. Компоненты вызывают методы сервиса, а не шлют сообщения сами.
- **Разовые запросы к OBS - `obsConnectionService.sendRequest`**: запрос встаёт в очередь, и сервис сразу запускает внеочередной опрос (`poll`), чтобы команда не ждала до секунды следующей пачки; если прошлая пачка ещё в пути, запрос уйдёт со следующей (`buildBatch`). Ответ отдельно не ждём. Так панель отправляет мосту команду обновления (`SetProfileParameter`).
- **Обновления - `services/updateService.ts`** (одиночка, `start`/`stop` вместе с `obsConnectionService` в `preload.ts` страницы `Core`). Обновления ставятся молча, как в Chrome: новая версия скачивается в фоне и начинает работать при следующем запуске OBS, никаких плашек (решение пользователя). Фоновую установку ведёт мост и обновлятор, панель для неё не нужна: сломанная панель всё равно получит исправление. Сервис нужен для карточки настроек: если включено `settings.isAutoUpdateEnabled` (по умолчанию да), проверяет последний выпуск при запуске панели и раз в сутки (таймер раз в час смотрит на `settings.lastUpdateCheckAt`), и это же показывает новую версию при ручной установке; выключено - панель сама в GitHub не ходит, работает только ручной `checkForUpdates`. Ответ 404 (выпусков нет) - «новых версий нет», время проверки пишется только при удачной проверке. `install` шлёт мосту `install:X.Y.Z` и пишет `request`, но только если нет блокировки `getInstallBlocker` (`utils/update`): нет выпуска, не новее текущей, у моста нет обновлятора (`update.available`), выпуск несовместим (`checkCompatibility` по версии OBS, протоколу, `availableRequests` из `GetVersion` и Chromium из `userAgent`), идёт обновление (статус моста не старше `UPDATE_STATUS_STALE_SEC`). Панель после установки не перезагружается. `setAutoUpdateEnabled` и появление моста с обновлятором (`onStoreChange`) шлют мосту `auto:on` или `auto:off`. `openReleasePage` открывает страницу выпуска: через мост (`OpenUrlCommand`), если мост есть и его версия не ниже `OPEN_URL_MIN_BRIDGE_VERSION`, иначе и в режиме моков - `window.open`.
- **Плашка «скрипт-мост не подключён в коллекции сцен» не закрывается**: без моста панель не работает толком, поэтому она пропадает только сама, когда скрипт подключён (решение пользователя; скрываемых подсказок и `settings.dismissedNotices` больше нет). Плашка - `pages/Core/containers/bridge-notice` под шапкой: показывается, когда панель подключена и мост не ответил на `BRIDGE_MISSING_CHECKS` (2, `pages/Core/consts.ts`) проверки подряд (`update.bridgeMissingChecks`: данных нет или они старше `BRIDGE_STALE_SEC` - 8 с при публикации раз в 3 с; удачная проверка и разрыв связи обнуляют счёт). Параметр моста и коллекцию сцен панель читает в каждой пачке опроса (раз в секунду). Мост пишет в данные имя своей коллекции (`sceneCollection`, `obs_frontend_get_current_scene_collection`) и публикует их сразу при загрузке и на `SCENE_COLLECTION_CHANGED`; панель засчитывает данные моста, только если имя совпадает с текущей коллекцией (`sceneCollection` у `parseBridgeData`, `getBridgeUpdate` и `getHardware`; данные без поля - от старого моста - принимаются). Имена коллекций в OBS уникальны, поэтому данные, оставшиеся в параметре профиля от моста прежней коллекции, отсекаются сразу, без порогов по времени. О переключении панель узнаёт из событий obs-websocket: `Identify` подписывается на категорию Config (`CONFIG_EVENT_SUBSCRIPTION`), `CurrentSceneCollectionChanging` ставит `connection.isSwitchingCollection` и сбрасывает мост (`resetBridge`, плашка прошлой коллекции пропадает сразу), `CurrentSceneCollectionChanged` записывает новую коллекцию, а флаг снимается на первой пачке после него, где OBS ответил на `GetStats` (или через `COLLECTION_SWITCH_TIMEOUT_MS`, 15 с, если событие потерялось). Пока флаг стоит, содержимое любой страницы приглушено: класс `.switching` (прозрачность и без нажатий) висит на обёртке `Outlet` в `MainLayout`, шапка и плашки не затемняются. Шапка `MainLayout` показывает рядом со статусом `Spin` и подпись текущего этапа загрузки (`main-layout/hooks/useHeaderStageView`, по приоритету): «OBS переключает коллекцию сцен…» (`header.switchingCollection`), «Получаю данные…» (`header.loadingData`: подключено, а карточек ещё нет), «Ищу скрипт-мост…» (`header.bridgeChecking`: данных моста нет, пропусков меньше `BRIDGE_MISSING_CHECKS`); подключение показывает сам значок статуса. Правило «старше 8 с» остаётся для запуска OBS сразу в коллекции без моста. Разрыв связи сбрасывает коллекцию и флаг переключения. По той же причине `discoverTargets` не пересобирает карточки, если OBS не ответил на `GetStreamServiceSettings` или `GetOutputList`: иначе при каждом переключении коллекции основная карточка на 5 с становилась «Stream» вместо площадки. Неудачный ответ на `GetProfileParameter` (OBS отклоняет запросы примерно секунду, пока переключает коллекцию сцен) проверкой не считается: `onBatchResults` обновляет данные моста и видеокарты, только если запрос прошёл, иначе плашка и пропадающие строки видеокарты мелькали бы при каждом переключении. Новой коллекции мост сам не достаётся: скрипты в OBS хранятся в каждой коллекции отдельно; коллекция сцен - `connection.sceneCollection` из `GetSceneCollectionList`. Путь к скрипту (`getBridgeScriptPath`) панель знает только по своему адресу `file:///<папка>/dock/index.html` (zip) или `file:///<папка>/versions/<версия>/dock/index.html` (установка), путь показывается `Typography.Text` с `copyable` (antd сам копирует и подписывает на своём языке); в dev-сборке пути нет. Заметки «площадку покажет скрипт» на карточках плагинов больше нет. Экран «нет связи» внутри OBS (`utils/isInsideObs`: `window.obsstudio` или `OBS/` в User-Agent) говорит, что, скорее всего, выключен сервер WebSocket, и показывает, где его включить и какой порт сверить; в обычном браузере - прежний текст. Секунды до повтора в этих текстах идут обратным отсчётом: сервис пишет время следующей попытки (`connection.reconnectAt`), а `Stats/containers/page/hooks/useConnectionAlertView` пересчитывает остаток раз в `RECONNECT_COUNTDOWN_TICK_MS`; когда время попытки наступило, а статус всё ещё «нет связи» (попытка идёт), вместо секунд - «Повторяю попытку…». Хвост про повтор - отдельные ключи `connection.retryIn` и `connection.retrying`, в текст он подставляется как `{{retry}}`.
- **Интерфейс обновлений** - только карточка `pages/Settings/containers/update-card`. Хук `useUpdateCardView` собирает результат из двух: `useUpdateProgress` (лестница ранних `return`: откат, ожидание моста, этап, готово, ошибка - что показать сейчас) и `useUpdateNotes` (кнопка «Обновить» или «Скачать вручную» и пояснения). В ней версия и «Что нового», время проверки, кнопка «Проверить обновления» с результатом, рядом с «Вышла версия X» - «Обновить» и «Что нового» или «Скачать вручную», если обновлятора нет или выпуск несовместим (тогда строкой - почему), свитч «Обновлять автоматически». Ход и результат берутся из статуса моста, и только если он про версию новее текущей и не старше запроса (`utils/isRequestedStatus`, с запасом `UPDATE_STATUS_CLOCK_SLACK_MS` на округление до секунд): этап и проценты со спиннером - пока статус идущего обновления не старше `UPDATE_STATUS_STALE_SEC`, «Версия X скачана и заработает при следующем запуске OBS» - после `done` (кнопка «Обновить» пропадает), текст ошибки и «Повторить» - после `failed`, в том числе фоновой установки, и если версия была откачена (`rolledBackVersion`, текст `update.errors.rolledBack`), пока не запрошена новая попытка. Без ответа моста 30 с после запроса - ошибка «скрипт не запустил обновление». Тексты ошибок - по кодам `Update-Widget.ps1` (`UpdateErrorEnum`), незнакомый код - `unexpected`.
- **Роутер - `createHashRouter`.** Адреса внутри `#`: обычные пути после Ctrl+R в OBS открыли бы несуществующий файл.
- **Ссылки строит `routerManager`** (`services/routerManager.ts`: `goToStats()`, `goToSettings()`, с `isHref` - только путь для `<Navigate>`), адреса строками не собираем.
- **Редиректы на вход и обратно - в `components/AppRoute`** по статусу соединения.
- **Диагностика - карточка в настройках** с кнопкой «Скопировать диагностику»: текст собирает `services/reportService.ts` (`buildDiagnostics`): общие строки о системе (`private buildEnvironmentLines`, их же берёт отчёт об ошибке), состояние скрипта-моста, видеокарта, объём памяти и список выходов. Ключей, паролей и адресов серверов там нет. Копирование - `reportService.copy`; если буфер обмена недоступен, текст показывается выделенным для Ctrl+C. Подписи «Скопировано» и «нажмите Ctrl+C» - общий раздел словаря `clipboard`.
- **Ошибки отрисовки ловит `components/ErrorBoundary`** (класс - иначе в React их не поймать), он обёрнут вокруг `Outlet` в `CorePage`, поэтому срабатывает раньше стандартной страницы react-router. Показывает `Result` с кнопками «Перезагрузить» и «Скопировать отчёт об ошибке» и сам отчёт в поле только для чтения; если буфер обмена недоступен, отчёт выделяется для Ctrl+C. Отчёт собирает `reportService.buildErrorReport`: версия виджета (`process.env.APP_VERSION` из `package.json`), версии OBS и obs-websocket (`GetVersion` в редких запросах, `connection.obsVersion`), язык, браузер, страница, время, стек. Паролей и ключей в отчёте нет. Подписи отчёта - на английском: он для разработчика, а не интерфейс.
- **Вход и настройки подключения.** Экран входа - для первого запуска и пароля, сменённого в OBS: порт (по умолчанию 4455) и пароль, `obsConnectionService.logIn`; он остаётся открытым и тогда, когда на порту никто не отвечает. В настройках порт и пароль - отдельные карточки со своими формами и валидацией. Смена пароля - `obsConnectionService.changePassword`: сохранённый пароль используется, пока OBS не примет новый, а результат (`PasswordChangeResultEnum`) показывается в карточке без перехода на вход. Поле порта общее - `components/PortField`.
- **Моки - свитч «Включить моки (для разработчиков)» в настройках** (`settings.isMockEnabled`, `obsConnectionService.setMockEnabled`). В этом режиме сервис не открывает WebSocket: `connect` создаёт `MockObsSimulator` (`utils/mock`) и ставит статус «подключено», а `poll` отдаёт ему те же запросы, что ушли бы в OBS, и передаёт ответы в `onBatchResults` - поэтому вся статистика работает как с настоящим OBS. Симулятор изображает YouTube основным выходом, Twitch через obs-multi-rtmp (появляется через 5 с, теряет кадры, переподключается), Kick и VK Video Live, видеокарту и память. Пока моки включены, под шапкой на всех страницах висит плашка с кнопкой «Выключить».

## Стили

- **CSS-модули (`.module.scss`)**, без БЭМ-функций и less.
- **Формы antd отправляются из `onClick` кнопки, а не через `onFinish`/`onSubmit` формы.** Обработчик `onSubmit` - асинхронная функция: берёт значения через `await form.validateFields()` (при ошибке валидации он отклоняется, и обработчик дальше не идёт; ошибки под полями antd показывает сам) и вешается на `onClick` кнопки отправки - `EnhancedButton` с `htmlType: 'submit'`, чтобы Enter в поле тоже отправлял форму. Так спиннер кнопки сразу работает, если в обработчик добавится асинхронный запрос. У формы - свой экземпляр `Form.useForm()`. Если форма в компоненте одна, её экземпляр называется просто `form`, а обработчик отправки - `onSubmit`.
- **Кнопки - только `EnhancedButton`** из `__components/EnhancedButton`, antd `Button` напрямую не используем. Пропсы кнопки - в `buttonProps`, подсказка - `tooltipProps`, подтверждение - `popconfirmProps`. Спиннер включён по умолчанию (`withSpinner`): чтобы он крутился, `onClick` должен вернуть промис; выключается `withSpinner={false}`. Кнопка без `type` - обычная кнопка antd по умолчанию, светло-синяя с обводкой: её цвета задают токены `Button` (`DEFAULT_BUTTON_COLORS`) в `utils/theme.ts`.
- **Текст рядом с кнопкой, значком или полем - всегда с заметным отступом, не вплотную**: подпись справа от кнопки (результат проверки у «Проверить обновления») - `gap={14}` у `Flex`, а не `small` (8 px).
- **Сначала возможности antd, потом свой CSS**: отступы - `Flex`/`Space` с `gap`, коробка - `Card`, текст - `Typography` с пропсами (`type`, `strong`). Свой CSS - для раскладки.
- **Инлайн-стилей нет никогда**: ни `style`, ни `styles` у компонентов antd, ни объектов `CSSProperties` в `consts.ts`. Внутренние части antd (`title`, `body`, `label`, `content`, `suffix`) правим через проп `classNames` классами из `style.module.scss`; чтобы перебить вложенные селекторы antd, класс части пишем внутри класса корня (`.card .title`, `.list .itemLabel`). Стиль по условию - условный класс (`content: isActive ? undefined : style.inactiveBitrate`), цвет из темы - CSS-переменной, а не `theme.useToken()`.
- **Цвета и отступы - CSS-переменными темы antd** (`var(--ant-color-border)`, `var(--ant-padding-xs)`, `var(--ant-margin-sm)`). Они доступны везде: класс `css-var-app` висит на `<html>`. Новые хексы в SCSS не пишем, тема - одна, в `utils/theme.ts`. `theme.useToken()` - только там, где CSS не достаёт: рисование на canvas и пропсы-цвета antd (`strokeColor` у `Progress`).
- **Все поля ввода светлее карточек**: фон любых полей (`Input`, `TextArea`, `InputNumber`, `Select`, `DatePicker`, `Cascader`, `TreeSelect`, `Mentions`) задаётся одним набором `FIELD_COLORS` в компонентных токенах темы `utils/theme.ts`. Новый тип поля - добавить его туда же, а не красить в SCSS.
- **Шрифт Inter - из пакета `@fontsource-variable/inter`** (импорт в `src/index.tsx`, в теме - `'Inter Variable'`), файлы woff2 webpack кладёт в `fonts/` сборки (`loadAssets`), а `copyReleaseFiles` - его лицензию OFL рядом (`dock/fonts/Inter-LICENSE.txt`). Внешних шрифтов и CSS по сети (Google Fonts и подобное) не подключаем: панель ходит только в obs-websocket и GitHub.
- **Своих размеров шрифта не задаём**: `font-size` и `font-weight` в SCSS - только переменными темы (`var(--ant-font-size)`), когда нужно вернуть части antd обычный размер.
- **Цвета площадок** (`PLATFORM_RULES`) - фирменные цвета, это данные, а не тема.

## Безопасность

- **Ключ трансляции не читаем и не показываем.** Из `GetStreamServiceSettings` берутся только `service` и `server`; скрипт-мост отдаёт только схему и хост сервера.
- **Пароль obs-websocket вводит пользователь**, хранится только в localStorage панели и сохраняется всегда после успешного входа (OBS сам держит его открытым текстом в своём конфиге). Сохранённый пароль в поля не подставляем.
- **Исключение - `npm run start:dev`**: dev-сервер отдаёт порт и пароль из конфига obs-websocket (`plugin_config/obs-websocket/config.json` в папке настроек OBS) по `/dev/obs-connection`, читая файл при каждом запросе, и слушает только `localhost`. Панель забирает их при старте, если собрана dev-сервером (`process.env.IS_DEV_SERVER`); в production-сборку этот код и пароль не попадают.
- **Личных путей и данных в репозитории нет** - он публичный.

## Выпуски

- **Версия - semver, источник - `version` в `package.json`** (в панель попадает как `process.env.APP_VERSION`). Номер выбирается по самому крупному изменению в выпуске: **major** - ломает установку или настройки (нужны ручные действия, несовместимый скрипт-мост, выше минимальная версия OBS); **minor** - новая возможность (функция, настройка, площадка, язык, карточка); **patch** - исправления и косметика без новых возможностей (иконки, стили, тексты, переводы). Пока версия 0.x, ломающее изменение идёт в minor и обязательно описывается в заметках. 1.0.0 - когда несколько выпусков подряд ничего не ломали и установка с обновлением устоялись.
- **Версия скрипта-моста - целое `BRIDGE_VERSION` в `obs-script/streamoscope-bridge/consts.lua`**, он отдаёт её в JSON как `bridgeVersion`. Повышается, только когда меняется формат его данных или панель начинает рассчитывать на новое поле. Панель и мост переключаются вместе при запуске OBS, но смена коллекции сцен перезагружает скрипты, и новый мост может встретить открытую старую панель: данные моста только дополняем.
- **Требования к окружению - `config/compatibility.json`** (минимальные версии OBS и Chromium). Остальное `scripts/packageRelease` берёт из кода: версию RPC - из `OBS_RPC_VERSION`, версию моста - из `BRIDGE_VERSION`, список запросов - из `ObsRequestTypeEnum`. Подняли требование - правим этот файл в том же изменении.
- **Сборка выпуска - `npm run package:release`**: production-сборка (имена файлов с хэшем содержимого, чтобы OBS не взял старое из кэша) и папка `release/streamoscope-<версия>/` с `dock/`, скриптом-мостом, `updater/`, `LICENSE`, `README.txt` и `compatibility.json`. Папка `release` в git не попадает. Скрипт - `scripts/packageRelease/`: `index.ts` только перечисляет шаги, каждый шаг - своя функция в своём файле (`buildCompatibility`, `copyReleaseFiles`, `writeReadme`, `writeCompatibility`); помощники одного шага лежат с ним в его папке (`buildCompatibility/` с `readNumberFromSource`, `readRequiredRequests`, `readSourceFile` и `index.ts`, который реэкспортирует шаг), текст `README.txt` для пользователя - шаблон `README.template.txt` с подстановкой `{{version}}`.
- **Как выпустить:** заметки `docs/release-notes/<версия>.md` (сначала английский, после `---` русский), затем `npm version <major|minor|patch>` (коммит и тег `v<версия>`) и `git push --follow-tags` - только по просьбе. Тег запускает `.github/workflows/release.yml` из двух заданий. `build` на Windows: проверяет, что тег совпадает с `package.json` и заметки есть, `npm test`, Pester (ставит Pester 5), Inno Setup (если его нет на машине - через choco), `npm run package:installer`, всё из `release/` - в артефакт. `publish` на Linux, только для тега: собирает zip, подписывает minisign установщик, zip и `compatibility.json`, проверяет подписи ключом `minisign.pub` из репозитория, пишет `SHA256SUMS.txt` и создаёт GitHub Release. К заметкам выпуска в конце дописывается скрытая строка `<!-- compatibility: {...} -->` с содержимым `compatibility.json`: панель читает её через API GitHub, потому что сами файлы выпуска странице `file://` недоступны (у `release-assets.githubusercontent.com` нет CORS). Секретный ключ есть только у `publish`. Тот же workflow можно запустить вручную (`workflow_dispatch`, `gh workflow run release.yml`) - тогда только `build`, без выпуска. На каждый пуш в `main` и pull request `.github/workflows/ci.yml` гоняет `npm test` и `package:release` на Linux и тесты Pester на Windows. Версии действий GitHub (`actions/checkout` и другие) держим на последних мажорных.
- **Обещания старым версиям - навсегда.** Обновление выполняет уже установленная версия, поэтому любая старая (хоть 0.1.0) должна уметь поставить самую новую. Никогда не меняем: формат `current-version.js` и `update-trial.txt` (их читает загрузчик моста, который обновляется только установщиком), верхнюю папку `streamoscope-<версия>` и обязательные файлы (`RequiredPackageFiles`) в архиве выпуска, формат тега `vX.Y.Z`, имена файлов выпуска (`streamoscope-setup-<версия>.exe`, `streamoscope-<версия>.zip`, `compatibility.json` и их `.minisig`), адрес выпусков `https://github.com/tjnk24/streamoscope/releases/download/v<версия>/`, ключ подписи (`minisign.pub`), строку `<!-- compatibility: {...} -->` в конце заметок и формат команды мосту `install:X.Y.Z`. Установщик продолжаем выпускать: версии до 0.5.0 обновляются только через него, и он сам раскладывает папку установки по-новому. В `compatibility.json` и строку совместимости поля только добавляем, существующие не удаляем и не переименовываем. Если без смены чего-то из этого не обойтись (например, ключ скомпрометирован), это ломающий выпуск: старые версии обновятся только вручную, и это пишется в заметках. Так было один раз - в 0.3.0 при переименовании obs-stats-widget в StreamoScope: 0.1.0-0.2.0 ищут файлы под старыми именами и до 0.3.0 сами не обновятся. Переноса со старой установки больше нет: ею пользовался только автор, и он перешёл вручную.
- **Ключ подписи:** публичный - `minisign.pub` в корне репозитория, секретный - только в секрете `MINISIGN_SECRET_KEY` репозитория, без пароля. Секретный ключ не читаем, не выводим и в репозиторий не кладём.

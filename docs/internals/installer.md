# Установщик и настройка OBS: как устроены

Форматы настроек OBS - `docs/obs-config.md`, правила PowerShell - `.claude/rules/windows/powershell.md`.

## Настройка OBS (PowerShell)

- **`installer/configure-obs.ps1` - точка входа** для Inno Setup: параметры (`-Mode Install|Uninstall`, `-InstallDirectory`, `-ObsDirectory` для portable, `-ConfigDirectory`, `-DataDirectory`), подключение функций из `installer/ConfigureObs/` и код выхода `ConfigureObsResult` (`0` готово, `1` ошибка и откат, `2` OBS запущен, `3` OBS ещё не запускали, `4` незнакомый формат, ничего не тронуто, `10` готово, но настроек obs-websocket ещё нет). На экран скрипт ничего не пишет: подробности - в `%LOCALAPPDATA%\streamoscope\configure-obs.log`, резервные копии - в `backups\<время>` рядом (последние 5).
- **Функции разложены по папкам** `installer/ConfigureObs/`: `json/` (разбор с позициями и экранирование), `ini/`, `files/` (чтение и запись с проверкой, резервные копии и откат, журнал), `edits/` (правки настроек OBS), `paths/` (поиск OBS, portable, пути, запущен ли OBS); в корне - `Invoke-ConfigureObs`, `Get-ObsChanges` и `ConfigureObsResult`. Точка входа и тесты подключают их рекурсивно (`Get-ChildItem -Recurse`), установщик копирует с подпапками.
- **Порядок:** OBS закрыт (`Test-ObsRunning`) → пути (`Resolve-ObsPaths`: portable, `[Locations]`, `user.ini` или `global.ini` по правилам из `docs/obs-config.md`) → все правки считаются в памяти, ошибка разбора - выход без записи → резервные копии → запись через временный файл с проверкой и `File.Replace` → при любой ошибке все файлы восстанавливаются из копий → `install-manifest.json` в папке установки (что добавлено, для повторной установки и удаления). Повторная установка ничего не меняет; удаление убирает панель (по `uuid` или адресу) и мост из всех коллекций, сервер WebSocket не выключает. `user.ini` никогда не создаём, пароль obs-websocket не читаем и не пишем в журнал.
- **Как устроены настройки OBS** - `docs/obs-config.md`; при новом знании о формате дополняем его.

## Установщик (Inno Setup)

- **Иконка - `installer/images/`**: `streamoscope.ico` (иконка `setup.exe`, деинсталлятора и записи в «Приложениях» - файл копируется в `{app}`), картинки мастера `wizard-<ширина>.png` (страница завершения) и `wizard-small-<размер>.png` (угол остальных страниц) в трёх масштабах 100/150/200 %. Та же иконка - `docs/images/streamoscope-icon-512.png` (README, вместо баннера; из неё же нарезаны остальные размеры) `obs-script/streamoscope-bridge/icon.png` (описание моста в окне скриптов OBS) и `src/images/streamoscope-icon.png` 64 px (фавикон - опция `favicon` у `HtmlWebpackPlugin`; в шапке панели иконки нет - решение пользователя). Новая иконка - пересобрать все эти файлы из одного исходника.
- **`installer/streamoscope.iss`, сборка - `npm run package:installer`**: `package:release`, затем `scripts/buildInstaller` находит `ISCC.exe` (Inno Setup 6: `ISCC_PATH`, `%LOCALAPPDATA%\Programs`, `Program Files`) и передаёт `/DAppVersion`, `/DPackageDir` (папка выпуска) и `/DOutputDir`. Результат - `release/streamoscope-setup-<версия>.exe`.
- **Раскладка установки**: `dock/index.html` - загрузчик из `installer/loader/index.html`, подставляет `current-version.js` и переходит на `../versions/<версия>/dock/index.html` с сохранением `#`; `streamoscope-bridge.lua` - загрузчик моста; `current-version.js` (`window.STREAMOSCOPE_VERSION = 'X.Y.Z';`, его читают оба загрузчика, установщик пишет его в `WriteCurrentVersion`); `versions/<версия>/` - содержимое папки выпуска; `updater/` - `minisign.exe` с лицензией; `update-trial.txt`, `healthy-version.txt` и `rolled-back-version.txt` - файлы автоотката; `ConfigureObs/` и `configure-obs.ps1`. `[InstallDelete]` удаляет старые файлы, все версии, `update-status.json` (иначе карточка показала бы статус версии, которой больше нет) и `update-check.stamp`: запуск установщика - чистая установка; `[UninstallDelete]` - `versions`, `current-version.js` и файлы автоотката, потому что их Inno не ставил. Адреса `dock/index.html` и `streamoscope-bridge.lua` записаны в настройках OBS и не меняются. Ctrl+R в доке перезагружает текущую версию из её папки, а новая откроется при следующем запуске OBS: так панель и мост всегда переключаются вместе. Сохранённые настройки не теряются: у всех страниц `file://` в Chromium одно хранилище.
- **OBS настраивает `configure-obs.ps1`**, установщик только запускает его скрыто (`Exec` 64-битного `powershell.exe`, `SW_HIDE`) и переводит код выхода в текст: `2` - окно «закройте OBS и повторите попытку» по кругу, отмена - установка без настройки; `3`, `4`, `1` и `10` - пояснение на последней странице, там же всегда - где искать панель и пароль WebSocket. Удаление (`InitializeUninstall`) запускает `-Mode Uninstall` до удаления файлов; если OBS открыт и пользователь не закрыл его - вопрос «удалить только файлы?», «нет» отменяет удаление.
- **`minisign.exe` для обновлятора** скачивает `scripts/buildInstaller/ensureMinisign.ts`: официальный архив minisign по точной версии и SHA-256 из `scripts/buildInstaller/consts.ts`, распаковка встроенным `%SystemRoot%\System32\tar.exe` (GNU tar из Git zip не распаковывает), кэш - `node_modules/.cache/minisign/<версия>`. В репозитории бинарника нет. Установщик кладёт его в `{app}\updater` вместе с лицензией `installer/third-party/minisign-LICENSE.txt` (ISC). Меняем версию minisign - меняем версию и хэш в `consts.ts`.
